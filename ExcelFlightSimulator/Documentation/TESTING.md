## v0.4 recorder and replay verification

The two-minute native run recorded 1,200 samples and rendered 2,560 frames at 21.33 FPS. The checks cover landing eligibility, personal bests, replay interpolation, camera rendering, input isolation, recording bounds and Excel debrief charts. The guided example scored 89/100. See Tests/results.txt and Tests/soak-result.txt.

## Earlier v0.3 continuous diagnostic

`run-soak.ps1 -Seconds 1200` exercises the real renderer, audio mixer, demo controller and fixed-step physics for 20 wall-clock minutes, cycling all seven weather presets and five cameras. It ignores desktop focus intentionally, so background inspection does not pause the diagnostic. It is not a physical-control test. `soak.csv` records elapsed/simulated time, frames, working set, GDI objects, audio refill and aircraft state; `soak-result.txt` contains the actual completion result. PERFORMANCE.md summarizes the final measurement.

## Visual and UI inspection

Inspected actual frame captures of the banked cockpit, focused instruments, approach/runway, low-poly aircraft, generalized hangars/apron, rain, sunset and night. The v0.3 physical UI check confirmed pause/resume, engine spin-down/restart, bank response, moving geography and normal exit. Rain deliberately reduces visibility; at cruise altitude the cockpit may hide most nearby ground. Texture pixelation, low-relief Richmond terrain, simple cloud shapes and generalized scenery remain visible limitations.

Verification caught and corrected fuel exhaustion regenerating idle RPM, an apron height mismatch, a diagnostic startup/audio problem caused by VBA label syntax, and an instrument-test region error. The source guard rejects procedure-name labels; it is not a VBA compiler. The workbook build fails on native FAIL results. Broader Office/DPI/hardware and sustained manual landing checks remain outside this release's evidence.

The final covering-window sizing change compiled and the native rendering suite passed. A post-build physical desktop recheck was unavailable because Windows Computer Use returned Access is denied. The physical v0.3 controls listed above were checked earlier, before that sizing change; they are not presented as a final fullscreen UI check.
